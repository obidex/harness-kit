## K078 · 2026-11-27 · STANDING — runner time counted by cause, once per job attempt; an unchanged revision tested again wakes nobody

**Asked.** A strategist's card on the owner's board (27 Nov 2026), widened to every project on the owner's word ("fix
it across the board") and corrected the same morning: two numbers per project from a weekly feed with no model call,
**avoidable runner-hours a week** and **how long a ready change takes to go green**; runs tied to the pull request and
the tested revision, not the branch name; each job attempt's minutes counted once, with "cancelled" as a flag; and a
rule for every project: an unchanged revision going through the same checks again wakes nobody. An earlier one-off
measurement had given causes that summed past 100%, because "cancelled midway" was a cause of its own beside the cause
that started the run.

**Measured** (21-27 Nov 2026, six days, every job attempt; the ERP's jobs half read). Avoidable runner-hours a week:
website 12.9 (39% of its CI time), infra 9.0 (19%), ERP at least 7.5 (35%), Control Center 0.6, roadmap 0.2. Most of it
is one cause in every project: the default branch testing a tree its pull request had already tested green (website
9.7 h, infra 6.9 h, ERP 4.8 h in the six days). A job GitHub dropped while it waited records a start time and no
runner: the first count took those as minutes and found 85 "cancelled hours" on the website; they held no machine.

**Decision.**
1. **`ci-repeats.mjs`** counts every job attempt once, as runner minutes (a job with no runner counts 0), in exactly one
   of seven causes (same, retry, bot, base, main, change, other; `metrics.md` §4), so the causes add up to the total.
   Cancelled is a flag inside a cause. Avoidable = same + bot. Content is the head on its base for a pull request run
   and the tree for the default branch. Runs are tied to their pull request by branch while it was open. It reads
   GitHub itself under a call budget, or takes a host's own records so a host that already reads every job (the VPS's
   minutes count) spends no call.
2. **The second reviewer keys to the change, not the commit.** A new head whose diff, with blob ids and hunk line
   numbers left out, equals a reviewed one gets no model call and no comment, so its thread is not woken.
3. **`ci.md` §6:** the rule above; a project whose numbers stand out gets its cause read, not a copied fix; no
   default-branch run cancelled half-way by the next merge; no merge of the base into a pull request where the
   repository does not require it, except to clear a conflict. Wakes and runner minutes are reported apart.

**Record.** `.harness/tools/ci-repeats.mjs`, `.harness/metrics.md` §4, `.harness/ci.md` §6, `.harness/tools/review.mjs`
(`changeKey`, `REVIEWED`), `.harness/review.md`. Checks: `tools/test-ci-repeats.mjs` (every cause, the sum, the flag,
a waiting job at 0, a restart after a dropped run as the first test, the base moving, a bot's own pull request, the
host's records, counts only on the page, the reader's budget) and `tools/test-review.mjs` (the same change on a new
commit: no call, no write). The reviewer's case fails without the change.

**Status:** STANDING.
