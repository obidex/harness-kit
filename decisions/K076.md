## K076 · 2026-11-27 · STANDING — every open request says its state in its own State line; `inbox.mjs state` moves a request filed by hand too, and blocked carries its reason

**Asked.** The owner's board, 27 Nov 2026, a strategist's line for the project that keeps the board: "every open
request carries a State line its holder keeps current, so nothing is unreadable." A project's health page
(the owner's status page) reads a request's state only from its `- **State:**` line. That day it
counted 16 open requests as "not read": cards filed by hand with the `inbox` label and no State line, which
`inbox.mjs state` refused ("not an inbox request"). A blocked request's reason was only in a comment, which
the page does not read.

**Decision.**
1. **A request filed by hand is a request.** An issue labelled `inbox` by a trusted author (a person with
   write access, or an App) with no inbox-id is moved with `state` like any other: the State line is added at
   the end of its body if missing, then replaced on each move; `done` adds the Evidence line if missing and
   closes it (K071). An issue without the label is refused, as before.
2. **Blocked says on what.** `state --to blocked --note <reason>` writes `blocked: <reason>` in the State
   line (one line, at most 160 characters), so the page shows what the request waits on. The comment is
   written as before.
3. **Kept current by its holder.** `inbox.md` "The issue": every open request says its state in its own
   State line, and its holder moves it as the work moves. A project whose board files cards by hand adds the
   line when the card is queued.

**Record.** `.harness/tools/inbox.mjs` (`withState`, `stateText`, `state`); `.harness/inbox.md`. Checks in
`tools/test-inbox.mjs`: a hand-filed request gets its line and blocked carries its reason; a later move
replaces the line; done adds Evidence and closes; an unlabelled issue, or a labelled one from an author without write access, is refused. They fail without the
change.

**Status:** STANDING.
