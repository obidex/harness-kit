## K079 · 2026-11-27 · STANDING — a known mistake is caught where it is made, a failed check says why in one line, and a release is tried on every project before it ships

**Asked.** A strategist's card on the owner's board (27 Nov 2026), on the owner's words: failures pop up too often;
solve the root issue across all projects. Of 13 failed runs counted across the projects, 8 were the kit's audit, and the
same family arrived three times in two days, each on a kit update. The card asked for: the audit's known-commit exception
to accept a verified word-for-word move out of a closed decisions log; "a new decision that points to the old one" as
the decisions tool's default, with a seconds-long check at the edit for C17 and every audit rule that failed twice; a
release tried read-only on every project before it publishes; one plain failure line from each kit check where the
status feed reads it; and a weekly first-pass rate per project with four causes and a short list of known causes.

**Found.** The audit's pull-request run skipped every change that did not touch kit, entry, agent or workflow files, so
a pull request that edited a decision merged green and the mistake surfaced on the next pull request that touched
`.harness/`, which is nearly always a kit update. The projects' audit logs show C17 (a decision edited, the closed log
losing lines, a cap) on two projects and O09 (attribution in bodies) as the rules that failed twice or more. A first
trial of the next release on the four projects found a red update already waiting: the kit's own pinned package
(`.harness/tools/agent-sdk/package.json`, K077) made every project's A17 ask for an `.npmrc`. The CC006-style move was
already acceptable through the baseline (K067); what was missing was the audit proving such a move itself, and an
answer for past edits of a written decision, which history keeps (it is never rewritten).

**Decision.**
1. **C17 proves a move itself.** A commit whose every line taken out of the closed log is, word for word and in order,
   the text of the decision files it adds is a verified move: the lost-lines test skips it with no baseline line and
   says so. Anything else lost still FAILs; the baseline's `commits` (K067, K073) still work.
2. **A past edit is answered by a newer decision.** A default-branch commit that changed a written decision is skipped
   by the never-edited test when a newer decision of the same series names that decision and at least 7 characters of
   the commit's SHA. `decisions.mjs new --supersedes <ID> [--commits <sha>,…]` writes that decision in the register's
   shape; the audit's C17 message names the exact command. An edit on the pull request itself always FAILs.
3. **The check at the edit.** `precheck.mjs` (about a second, no network) holds C17 and O09 for this change only:
   decision files changed, the log losing lines that are not a verified move, the register, caps and budget where the
   change touched them, attribution in a body (`--text`) or a commit message. `--install` writes the clone's own
   pre-commit and commit-msg hooks. `harness-audit.yml` runs it on every pull request, so the mistake fails the pull
   request that makes it. A rule that fails twice more joins it.
4. **The trial.** `trial.mjs` copies each project's current default branch, updates the copy to the candidate exactly
   as its kit update would be, and runs that update's kit checks (status, settings, precheck, the audit, the guard's
   content check); a project that pins no kit has its kit-facing settings read. Its last line names no project:
   `Trial: <G> of <N> projects green[; <P> red with the fix prepared][; <R> red] at <commit>`. `check-version` requires
   that line in every release's changelog entry, with no plain red. The per-project table goes on the private card.
   The kit's own public runner never reads a private project (its logs are public): the trial runs where the project
   access already is, in the session that builds the release, and costs no runner minutes.
5. **One plain line.** A failed audit rule, guard, decisions check or precheck writes one sentence (what failed, the
   next step) as an error annotation, which the check run's REST annotations return to the status feed, and in the job
   summary (`lib.mjs plainFail`).
6. **First pass with its causes.** `ci-repeats.mjs` adds per project: of the pull requests whose first run started in
   the window, the share green on their first judged head, and each failure's cause, one of four: infrastructure,
   unreliable test, old finding under a new rule, product defect (`metrics.md` §5). A deliberate failure is left out.
   Papercut reports take `--cause`; the weekly digest lists the known causes in one place, and a cause seen twice since
   its last fix asks for a prevention card, not another investigation.
7. **A17 counts the project's npm use only**, not the kit's own pinned package under `.harness/`.

**Record.** `.harness/tools/audit.mjs` (C17, A17), `decisions.mjs`, `precheck.mjs`, `trial.mjs`, `lib.mjs`, `guard.mjs`,
`ci-repeats.mjs`, `papercut.mjs`, `templates/workflows/harness-audit.yml`, `tools/check-version.mjs`; `decisions.md`,
`audit/README.md`, `metrics.md` §5, `papercuts.md`. Checks: `tools/test-decisions.mjs` 34-45, `tools/test-precheck.mjs`,
`tools/test-ci-repeats.mjs` 20-23, `tools/test-papercut.mjs` 40-43, `tools/test-replay.mjs` 17-20; each new behaviour
fails without this change.

**Status:** STANDING.
