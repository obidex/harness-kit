## K053 · 2026-11-20 · STANDING — the control repository's workflows travel with its pin

**Owner (20 Nov 2026, project chat).** "The hands-update gap (workflow files copied with the version)."

**Context.** A control repository pins a kit version and runs copies of that kit's `templates/hands/`
workflows. `hands-update` moved only the pin (K007), so the copies stayed at whatever release a session
last copied by hand: found six releases behind in November 2026, when a fix shipped in a template
(K050) reached nobody until a session copied all nine files.

**Decision.**
1. `hands-update`'s PR for the control repository carries the workflows too: the pinned kit's
   `hands.mjs control-update` copies the target release's `templates/hands/hands-*.yml` byte for byte into
   `.github/workflows/`, removes one that release dropped (it was a template of the pinned kit), writes the
   pin, and lists exactly the paths the PR stages. Any other workflow there is never touched.
2. Only the pinned kit's code runs (K007.7); the target release is read as data from its tag, whose
   `VERSION` must match.
3. `control-check` (the required `hands-check`) fails a copy that is missing or differs from the pinned
   kit's template. A control workflow therefore changes only in the kit.
4. The first move to this release is by hand once more (the workflow that copies is itself one of the
   copies); from then on the update carries itself.

**Known gap, not closed here.** The kit's Dependabot watches only its own `.github/workflows`, and
`check-kit` compares a template's pins only with actions those workflows use. An action only the templates
use is moved by nobody; a control repository's Dependabot proposes it against a copy, where item 3 now
refuses it. Moving those pins in the templates is the next kit card.

Homes: `hands.mjs` (`controlUpdate`, `controlCopyProblems`); `templates/hands/hands-update.yml`;
`hands.md`; `test-hands`.

**Status:** STANDING.
