## K082 · 2026-11-27 · STANDING — a coordinator's state note carries each owner ask as a separate item, and remarks in another field

**Asked.** A strategist's note on the owner's board (27 Nov 2026), on the owner's words: "some work is waiting but it
doesn't actually need me specifically do to anything, it shouldn't sit in needs you. what genuinely needs my human input
should sit there." For the kit, one rule: a coordinator's note carries its owner asks as separate items, each with three
parts (what he must do, why only he can, the link where he answers); no item means none; remarks go in another field and
are never read as an ask.

**Found.** The owner's status page counted "Needs you" from free text: the lines under any heading that reads like
"NEEDS OWNER", "NEEDS YOU", "OWNER WAITS" or "WAITING FOR YOU". Every project words that heading and its lines its own
way. The page's own filter learned to drop a bare "None from this run.", and the next note wrote "None from this run."
followed by remarks ("… will reach him … which is not an ask yet"), which counted again as one thing he must do. The
fault is in the source, not the filter: nothing said what an ask is.

**Decision.**
1. **One field, items only.** A state note has one heading `OWNER ASKS`. Under it, each line is one item,
   `- Do: <what he must do> · Why only you: <kind> — <why only he can> · Answer: <https link where he answers>`, or the
   one line `- None.`; no item means none.
2. **Why only him, from a fixed list.** `<kind>` is one of what the owner keeps (O01, the project instructions): `money`,
   `design`, `decision`, `sign-in`, `secret`, `account`, `his machine`, `setting`, `refused`. An ask that fits none of
   them is an agent's work, not his.
3. **Remarks elsewhere.** Anything else for him to know goes under `REMARKS`, which no reader counts. The older
   headings are not used, so no reader can count remarks under them again.
4. **Checked before it is written.** `state-note.mjs check` refuses a note without the field, a line in the field that is
   not an item, an item missing a part, a kind outside the list, an answer that is not a link, the field twice, a
   "None." beside an item, and an older heading. `state-note.mjs asks` gives the items as JSON: a status page counts
   those and nothing else.
5. **Where it is written.** `wake.md` "The STATE issue", point 7. C03's "Only you" list is this field. A project's run
   prompt names the check; a status page reads the field (its own change, through its inbox).

**Record.** `.harness/tools/state-note.mjs`; `.harness/wake.md` point 7; `.harness/lookups.md` (the state-note brief);
C03's record in `catalogue/core.md`. Checks in `tools/test-state-note.mjs`, each failing without the change. No
always-loaded text changed.

**Status:** STANDING.
