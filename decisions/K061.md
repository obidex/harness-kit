## K061 · 2026-11-22 · STANDING — on hosted minutes, both reviewer variables let the job start; the settings file still decides

**Found (22 Nov 2026).** The second reviewer, on a pull request adopting 0.54.0, saw that K060 point 4's
last clause says the opposite of the code: "there the variable switches it on and the file can only
shorten or end it".

**Decision.** On a private repository with no self-hosted `CHORE_RUNNER` or `RUNNER`, the job starts
only while the variables `REVIEW_FEDERATION_RULE` and `REVIEW_UNTIL` are both set, to any value (the
condition tests that they are set, not the date). Once the job starts, the settings file's `until`
decides, as K060 point 2 says, whatever date the variable holds. No behaviour change: this is what
0.54.0 does.

**Supersedes** K060 point 4's last clause ("there the variable switches it on and the file can only
shorten or end it"). The rest of K060 stands.
