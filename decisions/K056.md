## K056 · 2026-11-21 · STANDING — the wake job may start the run by its claim label alone: no token, no call outside GitHub

**Owner (21 Nov 2026, project chat).** On a proposal to stop depending on the outside start of a
scheduled task, he approved: finish the open label test, and "if the run starts, switch harness-wake
to end with a label and delete the API tokens". The change is only to how a run is started: "no cap,
no 'one run at a time' rule and no stop changes, and no timer that polls".

**Context.** K033 starts a run by calling the scheduled task's `/fire` address with a token kept as a
repository secret. For a task that lives inside a project that call was refused, which forced a second
task outside the project as a relay, and that relay broke when its session lost the tool it needed.
A test of the other way, a GitHub label starting the task directly, had been recorded as failed twice.
It had never been run: the test task's trigger was set to "pull request opened", so no label could
start it. With the trigger set to "Issue: Labeled" a run started 3 seconds after a label set by a
person's account and 2 seconds after one set by a job's own token.

**Decision.**
1. **`WAKE_START=label`** (an Actions variable) switches `wake.mjs fire` to the label start. Decision,
   caps, receipt and stops are the same code as before. The receipt is posted first; then the claim
   label `coordinator-running` goes on the STATE issue, and that `labeled` event starts the project's
   scheduled task through its GitHub trigger. No URL, no token, no request leaves GitHub.
2. **Nothing new to count or lift.** No new label, cap, timer or stop. One run at a time is the same
   claim. A label GitHub refuses or does not confirm is a failed start, recorded and counted like a refused
   `/fire`.
3. **Only a start the job signalled may work.** The trigger cannot tell who set the label. A run
   started by label first runs `wake.mjs started`, which passes only with the claim on the STATE
   issue and the job's own start receipt as its newest, at most 15 minutes old. Any other claim label
   starts a session that ends at once, so every run that works was counted first.
4. **The run proves its own start.** The job has no session link in this mode, so the run's first
   write is a comment on the STATE issue. Only the job sets the claim: a run or an agent never does,
   since with this start a claim is a start. A start that never comes is the existing dead-run case
   (the claim's 6 hours).
5. **`/fire` stays** for a project that has not switched; any value of `WAKE_START` other than
   `label` is `/fire`. A project that switches deletes its URL variable, its token secret and the
   task's API trigger.

**Not decided here.** Which projects switch and when: each by its own card. The trigger is set in the
scheduled task's own settings page, which no tool can write.

**Record.** `wake.md` "Start by label"; `tools/wake.mjs`; `templates/workflows/harness-wake.yml`;
`tools/test-wake.mjs` (the label-start checks). Extends K033; changes nothing in K051's caps.
