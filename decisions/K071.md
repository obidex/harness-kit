## K071 · 2026-11-26 · STANDING — where the weekly allowance goes: a measure from the threads' own session records

**Asked.** A strategist request on the owner's board (26 Nov 2026), Phase 0 of a plan to ship more per
weekly allowance: one table of use weighted by price, by project, model, role and what started the turn,
warm or cold; the heaviest threads and the largest tool results; calibrated against the allowance page;
kept as the baseline for every later check. Covered by the owner's approval of workflow improvements
(26 Nov 2026, 00:34 Damascus, recorded on the board). The owner's word the same day sets the goal: more
merged changes per allowance, not less work. A sister thread asked for two more figures: the share of use
from calls above 200k, 300k and 384k tokens of context, and the number of compactions.

**What was found.**
- The first waiting-share count (K070) was made by a script that lived in one thread and was not kept, so
  the "after" count had nothing to run.
- A cloud thread cannot open another thread's session file, and the allowance page has no API a thread can
  read. What a thread can read is other threads' records, through `list_threads` and `list_events`. Their
  results stay in the reader's own transcript, or in the file a long result is saved to.
- Each turn's `result` record carries what started it (`origin.kind`), its model calls (`num_turns`) and its
  price per model since the last turn (`model_usage_since_last_result`, `costUSD` at list price), subagents
  included. Each assistant record carries its model, its tokens and, for a subagent, its type.

**Decision.**
1. **`usage.mjs`** reads the records back from the transcripts: no key, no network. `next` prints the
   next `list_events` call to make, so a Haiku worker pages with no judgment. `table` gives the
   price-weighted table and the figures above. `merge` combines projects and calibrates dollars against
   a reading of the allowance page: dollars per point, and points per merged change per project.
2. **A wake** is a thread's turn from one `result` record to the next. Its model's price is shared over
   its calls by weighted tokens (input 1, cache read 0.1, cache write 1.25 for 5 minutes or 2 for an hour,
   output 5), which gives each subagent type its part. A wake is short when it ended within four model
   calls (A25). Its first main call is cold when it wrote more of its prompt to the cache than it read.
3. **`usage.md`** is the runbook: each coordinator measures its own project's threads and sends the JSON;
   Platform merges and calibrates. Records stay private: tables go on private issues, never into this
   repository.

**Record.** `.harness/tools/usage.mjs`, `.harness/usage.md`, the README row; checks in
`tools/test-usage.mjs`. Nothing always-loaded changed.

**Status:** STANDING.
