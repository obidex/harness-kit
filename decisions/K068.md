## K068 · 2026-11-25 · STANDING — a specialist pass: the full check with one fixed lens

**Asked.** An owner-approved credit plan (filed on the owner's board) asks for specialist passes over a
project's existing code before real data: "same tool, one lens each, strongest model", each with its own
cap, the first two (permissions; money and stock arithmetic) this week. `sweep.mjs` (K055) asked only the
general question, and a second run of it would continue the open full check, not start a new one.

**Decision.**
1. **A lens is a fixed name.** `harness-sweep` gains a `lens` choice: `none` (the full check, unchanged),
   `permissions`, `money-stock`, `irreversible`, `arabic-rtl`. The tool holds each lens's text; a run picks
   one by name (`SWEEP_LENS`, `plan --lens`). Free text, or a name not in the list, stops the run before any
   call, so nothing a person types reaches the question.
2. **Narrowed, not widened.** The system text says it is a specialist pass and asks only for defects under
   that lens. Everything else (tagged data, planted instructions as findings, graded headings, no code run,
   private repositories only, the reviewer's end time) is as K055.
3. **The high-risk model for every batch.** A pass reads less broadly, so every batch goes to the reviewer's
   high-risk model (today Opus 5.5), the strongest one the tool prices. A model it does not price is never called.
4. **Its own record and cap.** A pass keeps its own record issue ("Second reviewer: specialist pass (<lens>)
   of the existing code") and its own $30 cap, so it never continues, nor uses up, an open full check; its
   findings issues name the lens.

**Record.** `.harness/tools/sweep.mjs`; `.harness/templates/workflows/harness-sweep.yml`; `.harness/review.md`
"The full check of existing code"; checks in `tools/test-sweep.mjs` (each fails without the change).

**Status:** STANDING.
