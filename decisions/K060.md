## K060 · 2026-11-22 · The second reviewer's settings live in a file in the repository; an Actions variable counts only where the file is silent

**Owner (22 Nov 2026, the project's chat).** Approving a one-time use of the API credit, he asked first:
"move the reviewer's settings from Actions variables into a file in each repository, so no settings
page and no step from me. Every part ends by itself on 22 Dec 23:59 Damascus and nothing touches the
credit that arrives after that. Show ... where each off date lives before anything spends."

**Context.** K054 and K055 kept the reviewer's identifiers and its switch (`REVIEW_UNTIL`) in Actions
variables. A session cannot set one (the safety check refused setting another Actions variable the same
day), so every repository whose variables were missing stayed unreviewed, and each change of the end
time was a settings page for the owner. A variable is also invisible in history.

**Decision.**
1. **One file, the project's own:** `.github/harness-review.json` on the default branch holds `until`,
   `command`, the four identifiers, `sweep_rule` and lower caps, each optional. The job reads it from the
   default branch through the API (the full check from its checkout of that branch), never from a pull
   request.
2. **The file outranks the variable.** A variable is read only for a setting the file leaves out. A
   session cannot change a variable, so one that outranked the file would leave a stale end time only
   the owner could clear. Caps take the lowest of the built-in number, the file and the variable.
3. **K055 holds in the file.** `until` counts only beside a non-empty `command` naming the owner's
   command; `off`, a passed time, a time more than 45 days ahead, a file that is not one JSON object of
   known keys, or one that cannot be fetched, is off. Changing `until` is a pull request that quotes his
   command; no rule, schedule or agent pass writes it otherwise.
4. **No new hosted minutes.** On its own runner, or on a public repository, the job no longer waits for
   `REVIEW_UNTIL` to start: it reads the file and ends in seconds while off. On a private repository with
   no self-hosted `CHORE_RUNNER` or `RUNNER` it starts only where the variables `REVIEW_FEDERATION_RULE`
   and `REVIEW_UNTIL` are both set, as before, so being installed and off costs no hosted minutes; there
   the variable switches it on and the file can only shorten or end it.
5. A public repository keeps its identifiers in its variables and names only `until` and `command`.

**Supersedes** K055 point 1's "the switch is one more Actions variable" and point 2's "a session sets
or deletes `REVIEW_UNTIL`": the switch is `until` in the file, and a variable is its fallback. The rest
of K054 and K055 stands.

Homes: `tools/review.mjs` (`settingsOf`, `settingsText`, `switch`); `tools/sweep.mjs`;
`templates/workflows/harness-review.yml`, `templates/workflows/harness-sweep.yml`; `review.md`;
`test-review`, `test-sweep`; the kit's own `.github/harness-review.json`.

**Status:** STANDING.
