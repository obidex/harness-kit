## K080 · 2026-11-27 · STANDING — paid review calls cache what repeats, record what the cache saved, give the answer room, and let a project say what is not a defect

**Asked.** A strategist's card on the owner's board (27 Nov 2026), on the owner's words: what the API credit bought, why
it is so expensive, whether it is worth it, and no money wasted; "we should use cache more often since it's more cost
efficient". The card asked for prompt caching in the review, sweep and guide tools with cost per review before and
after; a fix for a large pull request the reviewer refused at its 8,000-token answer limit; and tighter specialist lenses
before any re-run, since two passes' triage dismissed 256 of 388 findings.

**Found.** No call set a cache marker, and the system text carried the call's random word, so even a marker could not
have matched from one call to the next. Every review's rulebook and every batch's rules were paid at the full input
price. The reviewer's answer limit counts the model's thinking: four reviews (two on the same change) ended with the
limit spent and no answer, about $1.20 for nothing. Most dismissals in the two lens passes fell into a few kinds: the
project had decided the thing on purpose (an interface left in one language until launch; example data in applied
migrations), a guard the model could not see in its batch, or a later migration that already changed an earlier one.

**Decision.**
1. **Cache what repeats.** The system text has no random word; the rulebook's tag ends in a word made from its own
   text, so the same rulebook gives the same bytes; both are marked for the five-minute cache and come first. The
   pull request, the diff and the files follow inside tags with a fresh random word. Both the reviewer and the code
   checks do this. The staff guide sends no marker: no two of its requests share a prefix within a cache's life, and
   it already runs at the Batch API's half price.
2. **Price and record what the cache did.** Fresh input, cache writes and cache reads are recorded apart and priced
   at their own rates (a read a twentieth of input, a five-minute write a quarter more; a write the API does not split
   is priced as the dearer one-hour kind). A worst case counts the cached prefix as a write. `review.mjs spent` gives
   the cost per review and the cache read share; a check's record shows its cache read share. A record from before
   this reads as before; an unreadable cache field counts as the dearest call.
3. **Room for the answer.** The answer limit is 16,000 tokens, the call may wait eight minutes and the job twelve. A
   change whose answer ran out of room is asked again at low effort. The call is streamed: unstreamed, fetch's own
   five-minute wait for the headers would end a long answer first (the independent review showed it at 301 s). A
   call that breaks after it was sent may be billed: the reviewer records it as `lost` with its model, counted at
   its worst case, and asks again; the code checks already count it as lost.
4. **A project's scope note.** `scope` in `.github/harness-review.json` (text, at most 3,000 characters): what the
   project has decided is not a defect. The code checks send it first in the rulebook and the model does not report
   it. Every check reports only what runs now and can be reached, and a defect in an earlier migration that later
   files it cannot see may have changed is said so and graded minor. The irreversible lens names the missing guard
   before it reports; the Arabic lens reports what breaks Arabic data the code takes in, not a screen left in another
   language by decision.

**Not done, and why.** The code checks stay on the Messages API rather than the Batch API: in this credit's window one
full check is left to run (worst case about $15), so a rewrite would save a few dollars at a larger cost in building
and review. It is the first lever for any later credit.

**Record.** `.harness/tools/review.mjs`, `sweep.mjs`, `templates/workflows/harness-review.yml`, `review.md`. Checks:
`tools/test-review.mjs` (prices, records, cached request, effort after an answer ran out of room, scope note) and
`tools/test-sweep.mjs` (cached request, records, cache share, scope note, tightened lenses); each fails without this
change.

**Status:** STANDING.
