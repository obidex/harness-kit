## K075 · 2026-11-27 · STANDING — a GitHub hiccup never leaves a change stuck: reads retry, a pull request's scrub check ignores the sweep, an optional check re-runs once, a ready kit update wakes its coordinator

**Asked.** The strategist's card on the owner's board, 27 Nov 2026, part B, after the owner asked about a
kit update pull request shown as "Stuck": "fix the root cause. don't just fix it one time just for it to
return later." The pull request's required checks had passed; only `harness-scrub` failed, 26 seconds in,
because GitHub answered one listing read with 502 "Server Error". `scrub.mjs` had no retry, so any error
ended the run red. Auto-merge was off by that project's settings, so nothing merged it; it waited for a
person.

**Decision.**
1. **One retry rule, in the one client.** `lib.mjs` `ghCall` tries a read (GET, HEAD) three times when
   GitHub answers 500, 502, 503 or 504 or gives no answer: 2 s, then 4 s apart (`HARNESS_GH_RETRY_MS`
   sets the step), one stderr line per retry, the last answer standing. Every kit tool that reads GitHub
   through it gets the rule (scrub, guard, audit, hands, stale, wake, review, papercut, rerun), and
   `inbox.mjs` keeps its exact copy for the tools a host fetches alone (`ask`, `explain`). A write is sent
   once: a 502 does not say it did not land, and a second comment, label or merge is worse than a red
   run the next run repeats. `metrics.mjs` and `notify.mjs` keep their own clients (fetched alone, not
   checks) and are unchanged.
2. **A pull request's scrub check is about that pull request.** A run started by a pull request's own
   event (`pull_request*`) fails only when its own body could not be read and cleaned. Once that body is
   clean, a sweep of other bodies that still fails after the retries is a warning. Because such a run can
   pass without its sweep, it never anchors the next sweep's window; a run from an issue or comment
   does, and it still fails when its sweep fails, so no green run moves the window past bodies it missed.
3. **One re-run of a failed optional check.** A new kit workflow, `harness-rerun` (`rerun.mjs`), on the
   `workflow_run` of a listed pull-request workflow: when that run failed on its first attempt for a
   pull request of the same repository, none of its failed jobs is a required check of the base branch
   (rulesets and branch protection), and no required check on the head failed (passed or still running),
   it starts the run's failed jobs once more. A second attempt is never re-run; a required check's
   failure is never re-run here. Its token writes only Actions.
4. **A ready kit update PR is merged, by auto-merge or by its coordinator.** Where auto-merge is allowed,
   `hands-update` already turns it on (unchanged). Where it is not (`allow_auto_merge` false, K023) or
   GitHub refused it, `hands-keep`, which runs while a kit PR is open, finds the PR "clean" or
   "unstable" (every required check and review passes) with auto-merge off, files one inbox request in
   that repository (`kit-update/merge-pr-<n>`) and wakes its coordinator through `inbox.mjs deliver`
   (label or wake channel), who merges it on its gates (O11). One request per PR. The App token of
   `hands-keep` gains `issues: write` for this; the App's own permissions are unchanged.

**Not changed.** No required check is loosened or skipped; nothing is paid. The App is never a merge
gate or a merger here: it asks. The wording of the owner's status page (part C of the same card) belongs to the project that builds it.

**Record.** `.harness/tools/lib.mjs` and its copy in `inbox.mjs`; `scrub.mjs` (`prOwn`, `sweepSince`,
`main`); `rerun.mjs` and `templates/workflows/harness-rerun.yml`; `hands.mjs` (`mergeWaits`,
`mergeRequest`, `keep`) and `templates/hands/hands-keep.yml`; `ci.md` section 2, `hands.md`. Checks:
`test-scrub` (502 once passes on the second try; 502 three times on the sweep leaves the pull request's
check green and the sweep to the next run; the same on a comment run fails it; a pull request's own run
never anchors), `test-rerun` (the decision, the run end to end, the workflow), `test-hands` (the merge
request filed and woken once, the token's issue permission). Each fails without its change.

**Status:** STANDING.
